# Barbacue — Storefront Redesign v3 (2026-06-24)

Driven by an owner complaint: *"o layout está muito simplista, a arte muito pouco chamativa"*
(too plain, art not eye-catching). A Playwright screenshot audit of the live local build
(197 products, 26 categories) confirmed three concrete problems. **Decisions here are authoritative.**

## Diagnosis (from baseline screenshots — `test-screenshots/baseline/`)

1. **Heroless header.** A tiny circular logo + name + generic tagline on a short dark band.
   The brand promise ("burguers na brasa" — flame-grilled) is invisible. Zero appetite appeal
   on first paint. No status (open/closed), no prominent WhatsApp/IG, no "ver cardápio" CTA.
2. **107 of 197 products have `imageUrl = NULL`** → they all render the *same* flat SVG ember
   placeholder. Whole categories (Acompanhamentos, Adicionais, Molhos, Turbine seu Lanche,
   Drinks, Sobremesas, Vinhos…) are walls of identical placeholders → reads as "broken /
   unfinished" (the owner's "imagens faltando"). NB: these are NOT broken `<img>` tags —
   Playwright reported 0 broken images; the CDN photos that *exist* load fine.
3. **Flat, low-personality styling.** Geist-only typography (no display face), uniform low-contrast
   cards, cramped price/CTA, plain category pills, and an **off-brand orange/amber chat panel**
   that clashes with the red/black brand. A hydration mismatch on the chat button
   (`bottom-24` vs `bottom-6`) also logged a console error.

## Decisions

### Art direction — generated with OpenAI `gpt-image-1`
All art is photoreal, **dark smoky background with live-fire ember accents**, deep reds + charcoal,
warm rim lighting, **no text, no logo, no people**. Saved to `apps/web/public/generated/`.
Each image is generated, then visually evaluated against this rubric; regenerated if it fails.

- `hero.png` (1536×1024) — flame-grilled smash burger on a glowing grill. The header background.
- Category fallbacks (1024×1024), used when a product has no `imageUrl`, chosen by category:
  `fallback-burger`, `fallback-sides` (fries/onion rings), `fallback-sauce` (dips/condiments),
  `fallback-drink` (sodas/juice), `fallback-beer` (beer & wine), `fallback-cocktail`
  (caipirinha/drinks), `fallback-dessert`, `fallback-combo` (burger+fries+drink tray).

`lib/category-art.ts` maps every category slug → a fallback key. `ProductImage` uses the
category fallback photo (object-cover) before the SVG mark, so no card looks "missing" — a
repeated appetizing category photo reads as intentional branding, not a broken image.

### Typography & theme
- Display face **Anton** (Google) for the wordmark + section headings (uppercase, grill-poster
  energy); **Geist** stays for body/UI. Two-font system, loaded via `next/font/google`.
- Theme tokens kept (warm charcoal `--bg #0e0b0a`, `--brand-red #ed1b24`, tan accents) but
  extended with reusable utilities: hero/scrim gradients, `.section-title`, `.btn-brand`,
  `.card-scrim`, fire-glow accents.

### Layout
- **`Hero`** (new server component): full-bleed `hero.png`, dark vertical scrim, big **BARBACUE**
  wordmark, brand tagline, an **Aberto/Fechado** status pill, info chips (hours / delivery / address),
  and CTAs (Ver cardápio ↓, WhatsApp, Instagram). Replaces the thin profile header.
- **Sticky `CategoryNav`** gains a per-category emoji and a brand-red active glow.
- **`ProductCard`** upgraded: gradient scrim on the image, larger price, promo ribbon, refined
  Add/stepper, consistent card height, hover lift.
- **`ChatAgent`** rebranded orange → brand red/ember; hydration class mismatch fixed.

### Local data note
The dev DB tagline/WhatsApp were thin, hiding header CTAs. For representative screenshots the
local `store_settings` row is set to the brand tagline + a WhatsApp number. Code degrades
gracefully when these are null (CTAs simply hide). This is a **local-only** data tweak; prod
settings are owner-managed.
